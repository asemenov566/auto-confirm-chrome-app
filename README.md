# Auto Confirm

Лёгкое расширение для Chrome и Microsoft Edge, которое автоматически нажимает «ОК» в системных окнах JavaScript `confirm()` на выбранных сайтах.

Добавьте домены и включите переключатель. На остальных сайтах подтверждения работают как обычно. Когда расширение выключено, оно не подменяет `confirm()`.

**Без регистрации, серверной части и установки Node.js.** Все настройки сохраняются в профиле браузера.

## Возможности

- Компактный попап с переключателем, который запоминает своё состояние.
- Управление доменами в отдельном окне или обычной вкладке.
- Поддержка кириллических доменов, HTTP и HTTPS.
- Изменение настроек на открытых страницах без перезагрузки.
- Необязательный JSON-файл с предустановками и исключениями.
- Никакой аналитики и передачи содержимого страниц на сервер.

## Установка

1. Скачайте проект через **Code → Download ZIP** или готовый архив из [Releases](https://github.com/asemenov566/auto-confirm-chrome-app/releases).
2. Распакуйте архив в постоянную папку.
3. Откройте `chrome://extensions` в Chrome или `edge://extensions` в Edge.
4. Включите **режим разработчика**, нажмите **«Загрузить распакованное расширение»** и выберите папку [`extension`](extension).
5. Закрепите Auto Confirm на панели браузера.

Расширение первоначально **выключено**, список сайтов пуст. Node.js и npm нужны только для разработки и тестов.

Для обновления замените файлы в той же папке и нажмите **«Обновить»** на карточке расширения. После обновления перезагрузите открытые страницы, на которых используете автоподтверждение.

## Использование

| Элемент | Действие |
| --- | --- |
| Переключатель | Включает или выключает автоподтверждение для всего списка |
| Шестерёнка | Открывает окно управления доменами |
| Стрелка вправо | Открывает те же настройки в обычной вкладке |
| «Добавить» / «Удалить» | Изменяет список сайтов; изменения сохраняются сразу |

Введите только домен, например `shop.example.com`, без `https://`, пути и порта. Сопоставление точное: `example.com` и `www.example.com` — отдельные записи. Кириллические имена поддерживаются. Настройки общие для окна и вкладки.

Автоподтверждение распространяется на **все** вызовы `confirm()` на выбранном домене, включая подтверждение удаления. Уже открытый системный диалог расширение не закрывает.

## Предустановки и исключения

Этот раздел необязателен: сайты можно добавлять через интерфейс без каких-либо файлов.

Для общей конфигурации скопируйте [`extension/exceptions.example.json`](extension/exceptions.example.json) рядом под именем `exceptions.json` и замените примеры своими доменами:

```json
{
  "domains": [
    "blocked.example.com"
  ],
  "presets": [
    "test.example.com",
    "shop.example.com"
  ]
}
```

| Поле | Назначение |
| --- | --- |
| `domains` | Домены, которые запрещено добавлять |
| `presets` | Домены, которые автоматически добавляются в список |

Исключения имеют приоритет: запрещённые домены пропускаются при импорте и убираются из сохранённого списка после синхронизации. При попытке добавить такой домен вручную поле молча очищается.

Файл перечитывается при запуске фонового обработчика, открытии попапа или настроек и действиях пользователя. После редактирования достаточно заново открыть попап. Новые предустановки добавляются без дублей; удалённые через интерфейс не возвращаются при каждом запуске. Удаление записи из `presets` не удаляет уже импортированный сайт — используйте интерфейс или `domains`.

Рабочий `exceptions.json` не входит в Git и релизный архив. Без него используются пустые предустановки и исключения, а сохранённые настройки пользователя остаются. Сам шаблон автоматически не загружается. Некорректный JSON нужно исправить: расширение покажет ошибку конфигурации.

Браузер не разрешает расширению записывать файлы в собственную папку. Создать JSON можно вручную в текстовом редакторе или командой разработчика:

```sh
npm run prepare-config
```

Команда создаёт файл с пустыми массивами только при его отсутствии; существующий файл не перезаписывает.

## Данные и разрешения

Список сайтов и состояние переключателя хранятся в `chrome.storage.local`. Они сохраняются после перезапуска браузера, не синхронизируются между устройствами и удаляются при удалении расширения.

| Разрешение | Для чего нужно |
| --- | --- |
| `storage` | Сохранение настроек |
| `scripting` | Подключение и отключение перехвата `confirm()` |
| Доступ к HTTP/HTTPS-сайтам | Добавление произвольных доменов через настройки |

Широкий доступ к сайтам нужен для редактируемого списка. Само автоподтверждение включается только для доменов из него. Расширение не собирает содержимое страниц, cookies или историю посещений.

## Совместимость и ограничения

- Chrome 111+ и Microsoft Edge на Chromium. Браузерные проверки выполнялись в Edge; другие Chromium-браузеры отдельно не проверялись.
- Обрабатывается только `window.confirm()`. HTML-попапы сайта, `alert()`, `prompt()`, запросы разрешений и предупреждения о несохранённых изменениях не затрагиваются.
- Поддерживаются HTTP/HTTPS-страницы и соответствующие списку iframe. Служебные страницы браузера, `about:blank` и `srcdoc` не поддерживаются.
- Сохранённая до подключения ссылка на исходный `confirm()` и последующее переопределение этой функции сайтом могут обойти перехват.
- Если браузер не поддерживает отдельные окна расширений, используйте стрелку для открытия настроек во вкладке.

## Разработка

Всё устанавливаемое расширение находится в [`extension`](extension); сборка JavaScript не требуется. В [`scripts`](scripts) — подготовка конфигурации и упаковка, в [`tests`](tests) — проверки с вымышленными доменами и отдельными браузерными профилями.

Для локальных проверок нужен Node.js 22+:

```sh
npm test
```

Для браузерных проверок:

```sh
npm ci
npx playwright install chromium
npm run test:browser
```

По умолчанию используется тестовый Chromium. Для установленного Edge задайте `BROWSER_CHANNEL=msedge`. Playwright — только тестовая зависимость; в расширение он не входит. Проверки подменяют ответы сайтов тестовыми страницами и не используют личную конфигурацию.

### Подготовка архива

В Windows выполните из корня проекта:

```powershell
powershell -NoProfile -File scripts/package.ps1
```

Архив появится в `dist/`; версия берётся из [`manifest.json`](extension/manifest.json). Упаковка использует явный список файлов расширения и включает обезличенный шаблон конфигурации. Личный JSON, тесты, профили, скриншоты, зависимости и служебные файлы Git в архив не включаются. README остаётся в репозитории. Создание архива ничего не публикует на GitHub.
